# 截图批评循环（Capture & Critique Loop）

> 把"单次生成"变成"生成-评估-重写"，这是逼近 Opus 质量的关键。

## 流程

\`\`\`
1. AI 产出分镜 DSL (JSON)
2. 引擎渲染，在 N 个关键时间点截图
3. 每张截图 + 反模式警告 → 交给视觉批评（人或视觉模型）
4. 批评产出：保留什么 / 改什么 / 加什么
5. AI 按批评改 DSL，回到步骤 2
6. 迭代 2-4 轮，挑最佳版本
\`\`\`

## 关键截图时间点

不要均匀采样。用**分镜检查点**策略 —— 挑"叙事结构"上的关键帧：

| 位置 | 目的 |
|---|---|
| 开场 (0.05 × duration) | 检查氛围/底噪是否铺得住 |
| 上升期 (0.3 × duration) | 检查是否有多层活动 |
| 高潮 (0.65 × duration) | 检查主视觉是否成立 |
| 收束 (0.85 × duration) | 检查结尾是否有落点 |
| 收尾 (0.95 × duration) | 检查文字/总结是否干净 |

## 批评清单（给视觉模型或人）

每张截图回答这几个问题：

1. **视觉重心**在哪？是否明确？（找不到重心 → 加聚焦元素）
2. **层次**够不够？至少 3 层（底噪 / 中层动 / 前景）？
3. **颜色**是否协调？有无"AI 屏保"式的高饱和彩虹？（→ 换调色板）
4. **动感**能感觉到吗？还是看着像静态图？（→ 检查是否有横向流动/旋转/呼吸）
5. **文字**位置对吗？压在主体上吗？（→ 移到 0.15 或 0.85 的 y）
6. 有没有**过曝/过暗**？（→ 调 bloom threshold / vignette）
7. 有没有**明显穿帮**？(元素被裁掉、帧间跳变)
8. 整体**像"成品"还是像"半成品"**？

## 自动化

浏览器 console 里可以直接跑：

\`\`\`js
// 截图（返回 base64）
const shot = (t) => {
  window.__rf_runtime.seek(t);
  return window.__rf_runtime.canvas.toDataURL('image/jpeg', 0.85);
};

// 反模式检测
const warns = RF.lintStoryboard(window.__rf_runtime.storyboard);
console.table(warns);
\`\`\`

## 未来的自动化方向

- Playwright / Puppeteer 脚本遍历时间点 → 存图
- 图喂给视觉模型（GPT-4V / Claude）→ 产出结构化批评
- 批评 → prompt → 让 AI 改 DSL
- 循环直到批评清单全绿或达到轮数上限

（当前项目走的是浏览器内截图 + 手动上传给 AI 的路线，因为工具链更稳。）
